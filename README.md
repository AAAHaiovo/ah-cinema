# AH 影视

个人自用的影视 PWA。前端是纯静态的原生 HTML / CSS / JavaScript，**不需要登录、不需要构建工具**；Windows 浏览器和 iPhone 主屏幕都能用。v0.5.0 起增加**可选的**源管理与多源点播搜索，需要一个自己的 Vercel / 腾讯云 EdgeOne Pages / SCF / 本地 Node 服务来转发源请求（浏览器跨域所限）。v0.6.0 起首页直接显示已启用源的最新影片；v0.7.0 起支持按源分类筛选和上一页 / 下一页翻页；v0.8.0 改进播放失败的诊断与 HLS 自动兜底；v0.8.0 把分类整理成「电影 / 电视剧 / 动漫 / 综艺 / 纪录片 + 子类型」，翻页按源站真实页数显示并支持跳页，同时支持源站的 Apple CMS XML 接口（`/at/xml/`）；v0.8.1 把「更多」改成 iOS 风格的内嵌展开网格，并给桌面 / 主屏图标加上超椭圆圆角；v0.8.2 在服务端按 `type_id` 二次过滤分类结果（即使源站忽略 `t` 参数），HTTPS 视频默认直连、失败才切代理，减少播放卡顿；v0.8.3 优化播放器与日常使用：横屏选集紧凑网格、返回键回到简介、搜索记录可多选删除或一键清空、下滑隐藏分类栏、界面文字禁止长按复制、播放器图标重绘与过渡动画、每次进入重置横竖屏，以及更完整的全屏处理；v0.8.4 把搜索记录的删除改成原位勾选（「清除」旁边的「全部清除」一键清空），选集改为右侧滑出抽屉并在打开时把当前集滚到列表中间，播放器图标再加大加粗；v0.8.5 重做观影界面：毛玻璃圆形按钮、居中大播放键、带剩余时间的胶囊进度条（如 `-04:03`），并把「横屏 / 全屏」合并成同一个按状态切换的按钮（物理横屏下点它就是全屏）；v0.8.6 继续微调播放器：按钮缩小、图标加粗，缓冲转圈与播放图标同尺寸，重画 ±10 循环箭头，降低毛玻璃模糊，进度条下移，右下角显示模式按钮常驻；v0.8.7 再修 ±10 箭头与转圈尺寸，进一步缩小模糊和按钮、下移进度条，并让 Service Worker 绕过 HTTP 缓存、发现新版本时自动刷新页面；v0.8.8 按标准图标重画 ±10 秒（闭合圆环 + 压在上面的实心箭头），静音键移到左下角，清晰度 / 倍速改成贴右下角的浮动卡片，全屏按钮回到控件行并随控件一起隐藏，进度条去掉高斯模糊、改用 App 同款红色进度，播放键放大且缓冲转圈与它同尺寸，并把首页改成固定外壳：顶栏和底部栏永不移动，只有分类栏在下滑时收起、上滑时出现；粘贴链接的入口在「我的视频」；v0.8.9 按参考图重排播放器：底部横向进度条两端显示当前时间与剩余时长，画面中央竖排「后退 10 秒 / 播放暂停 / 前进 10 秒」，右上角投屏与关闭，右侧竖向音量条，左下角保留线路与清晰度菜单组；切到横屏时尽量自动全屏，横屏状态栏改为透明样式，回到竖屏恢复原生状态栏；悬浮控件统一改用 iOS 18 风格的深色高斯模糊，缓冲转圈缩小到暂停图标大小；v0.8.10 再按参考图精简播放器：线路与清晰度只保留「线路」，±10 秒按钮移到播放键左右并重绘为开口圆环 + 箭头 + 数字 10，删除投屏，声音只保留静音开关，选集移到右上角，新增 iPhone 全屏按钮，双击画面空白处可暂停 / 继续；v0.8.11 修正 ±10 箭头（箭尾短杆连接圆环、箭头尖端朝外），全屏移到右下角横屏键右侧，静音移到右上角选集左侧，并让物理横屏与强制横屏的控制位置保持一致；v0.8.12 按参考图再画 ±10 图标（实心箭头顺着圆环端点伸出、指向斜上），并修复物理横屏转回竖屏后播放器按钮点不动的问题（视口稳定后重建布局，控件隐藏时第一次触摸即可唤出）；v0.8.13 把横屏（物理横屏与强制横屏）的静音 / 选集 / 关闭移到画面右上角，与竖屏一致。

**线上地址**：<https://aaahaiovo.github.io/ah-cinema/>（纯静态备用入口；iPhone 用 Safari 打开 → 分享 → 添加到主屏幕）

## 现在能做什么

### 首页片库（v0.6.0，v0.8.0 重做分类与翻页，v0.8.1 改进分类展开，v0.8.2 修正分类准确性，v0.8.3 下滑隐藏分类栏，v0.8.8 顶栏 / 底栏固定，只有分类栏收起）

配置好源之后，首页「最新影片」会自动拉取所有已启用源的最新入库列表，以海报墙显示；两个源里的同一部影片会合并成一张卡片。

顶部「AH 影视」栏和底部导航栏固定不动；页面内容在两者之间单独滚动，只有两级分类栏会在下滑时收起、上滑或回到顶部时重新出现：

- 第一行：**全部** + **电影 / 电视剧 / 动漫 / 综艺 / 纪录片**；只显示源里确实存在的组。
- 第二行：选中一级分类后出现子类型，例如电影下的剧情 / 喜剧 / 爱情 / 动作 / 科幻 / …。先显示 9 个；超过 9 个时行尾出现「展开」，点开后分类栏内直接铺开全部类型网格（可上下滚动），再点「收起」返回；当前选中的类型即使排在后面也会留在可见行里。
- 分类优先按源站的 `type_pid` 父子关系整理；源站没有父子关系时按分类名推断。分类名本身明确写了「动漫 / 电视剧 / 电影 / 综艺 / 纪录片」时以名称为准，避免源站错误嵌套。
- 不同源对同一分类的 `type_id` 可能不同，App 会按「分类名 → 各源 type_id」映射后分别带 `t` 参数请求。如果源站忽略 `t`（直接返回全部影片），服务端会按列表项的 `type_id` 再过滤一次；没有 `type_id` 的源无法校验，保持原样。
- 「电影 → 全部」会聚合该组所有子类型的 `type_id`，某次请求失败只标记为「部分分类失败」。
- 两行都可以横向滑动（触屏直接拖动，桌面端还会显示左右箭头）；展开网格时不会弹层，也不影响横向滑动。
- 分类栏下方显示约数（各源合计，可能重复）、可用源数和当前页 / 总页数。

分页器的总页数来自源站返回的 `pagecount`，不再固定为 20 页；底部有「上一页 / 下一页 / 跳转」，跳转页码会校验范围。切换一级分类或子类型都会回到第 1 页。右上「刷新」重新加载；某个源失败时只显示失败提示，不影响其他源。没配置源时，首页会提示去「我的 → 源管理」添加。

### 粘贴链接直接播放

粘贴入口在「我的视频」页。点「粘贴链接」，把链接粘进去：

| 链接类型 | 例子 | 播放方式 |
|---|---|---|
| 视频文件直链 | `https://example.com/movie.mp4` | 浏览器原生 `<video>` 播放 |
| 视频文件直链 | `.webm` / `.mov` / `.ogg` / `.m3u8` | 同上；HLS 在 Safari / iPhone 原生播放，桌面 Chrome / Edge 自动加载 hls.js |
| 哔哩哔哩视频页 | `https://www.bilibili.com/video/BV1xxxxxxxxx` | B 站官方嵌入式 iframe |
| 哔哩哔哩 BV 号 | `BV1xxxxxxxxx` | 同上 |

- 播放过的链接会保存到「我的视频」，下次点开就能看；首页只显示源里的影片。
- 同一个链接不会重复添加；B 站同一 BV 号只保留一条。
- 网页、网盘分享页、平台会员页这类链接**不会被解析或抓取**。App 会提示「只能直接播放视频文件直链」；你仍可选择尝试，但能不能播完全取决于该地址本身。
- 无效地址（不是 `http://` / `https://`）会直接提示，不添加任何内容。
- `http://` 直链在 GitHub Pages 这类 HTTPS 页面里可能被浏览器当作混合内容拦截，优先用 `https://`。

### 源管理、首页片库与多源搜索（v0.5.0 起，v0.7.0 增加分类与翻页）

这是按 LibreTV 的使用方式做的能力，但**不带任何内置源**：

- **源管理**：在「我的 → 源管理」里添加你自己的 Apple CMS 接口（`ac=list` / `ac=videolist`）。地址可以是 JSON，也可以是 `/at/xml/` 目录式 XML；末尾斜杠会保留。添加时必须勾选授权确认；重复地址会被拒绝；可以启用 / 停用 / 测活 / 编辑 / 删除。表单会提示：局域网地址（`192.168.x.x` 等）仅本地开发模式可用，线上请填公网可访问的 API 地址。
- **首页片库**：已启用的源按 `ac=videolist&pg=N` 拉取最新影片，合并同名片目，支持刷新、两级分类筛选、上一页 / 下一页和跳页。
- **分类目录**：服务端并行请求各源的 `?ac=list`，读取 JSON 的 `class` 或 XML 的 `<class><ty>`，过滤明显成人分类后整理成父子分类树；客户端再把选中的分类映射成各源的 `t=type_id`。单个源的分类请求失败只影响该源。
- **两种接口格式**：服务端按响应内容自动识别 JSON / XML。XML 解析拒绝 `DOCTYPE` / `ENTITY`（防 XXE 与实体膨胀），限制嵌套深度和元素数量；非 UTF-8 响应会按 `Content-Type` 或 `<?xml encoding>` 解码。
- **订阅**：支持 LibreTV-SourceList、裸数组、TVBox 的 JSON CMS 站点列表；不导入直播源。同步失败不会删除已有源。
- **服务连接**：GitHub Pages 版需要填写你的 Vercel 服务地址和访问口令；Vercel / 本地同源部署留空即可。口令只保存在这台浏览器。
- **多源搜索**：在搜索页按回车或点最近搜索，最多同时请求 8 个已启用的源；结果按「标题 + 年份」合并，显示每个源的成功 / 超时状态。一个源失败不影响其他源。
- **播放**：点结果卡片，多来源时先选源；解析出的多线路、多集进入现有详情页 / 播放器，支持切线路、续播、收藏。HLS 由 hls.js 播放，签名代理 URL 自动处理跨域和 HTTP 混合内容。
- **健康退避**：同一个源连续两次搜索失败会冷却 10 分钟；测活成功立即恢复。

> 服务端只请求 Apple CMS 的 JSON / XML 接口，不抓取 HTML 详情页，不做网页解析。搜索结果、详情和播放地址都来自你自己添加的源。

### 所有功能

- 首页：源片库「最新影片」海报墙（刷新、两级分类筛选、约数与跳页、多源合并、JSON / XML 源）、继续观看、我的视频入口
- 我的视频：粘贴链接 / 选择本机视频；列表、删除（同时清理进度和收藏）
- 搜索：本地链接 / 本机文件即时搜索 + 网络源搜索（回车触发，最多 8 个源），结果按片名分组
- 源管理：添加 / 编辑 / 测活 / 启停 / 删除你自己的授权源，JSON 订阅同步，导入导出
- 多线路播放：远程详情支持多线路、多集，播放页可切线路；签名代理处理 HTTP 分片与 m3u8 重写
- 历史：观看记录、继续观看
- 收藏：收藏链接或本机视频，单独一页
- 详情页：标题、标记（网址 / 本机 / B站）、来源、片源类型、简介、进度、播放入口
- 播放器：播放/暂停、后退 10 秒、前进 10 秒、进度条、清晰度、倍速、静音、**横屏/竖屏切换**、全屏、返回

- 本机文件：选一个本地视频（≤ 2 GB），存进 IndexedDB，自动截一帧做封面；刷新和重开 App 后仍在，可完全离线播放
- 白天 / 黑夜 / 跟随系统三档主题（白灰红 / 黑灰暗红），刷新不闪白
- iOS 风格：底部标签栏、桌面侧栏、圆角卡片、底部弹出面板、原生感按钮
- AH 标识：顶栏、启动页、空状态、About 页；App 图标为品牌红底 + 白 AH
- PWA：可安装到 Windows 桌面 / iPhone 主屏幕；Service Worker 缓存应用壳，**断网也能打开 App**
- 本地数据：IndexedDB（不支持时自动降级），可导出/导入 JSON 备份

## 怎么用

1. 打开 App，先到「我的 → 源管理」添加你自己的授权源；首页会自动显示这些源的最新影片。
2. 想播放自己的链接或文件：进入「我的视频」→「粘贴链接」或「选择本机视频」。
3. 播放过的内容会留在「我的视频」和「历史」里；播放到一半退出，下次会自动续播。
4. 常用内容点详情页的收藏；收藏在「我的 → 收藏」。
5. 换手机或清理浏览器前，到「我的 → 设置 → 导出备份」留一份 JSON（本机视频文件本身不在备份里，需保留原文件）。

**不支持**：解析普通网页里的视频、网盘分享页、会员专享页、直播流、DRM 加密内容，以及绕过平台限制。B 站番剧、会员内容也可能无法嵌入，此时用播放页右上角「在 B 站打开」。

## 本地预览（Windows）

需要先安装 Node.js。当前开发机是 Node v24。

```bash
cd "C:\Users\24751\Desktop\新建文件夹\影视"
node tools/serve.js 4173
```

浏览器打开 <http://127.0.0.1:4173/>。

这个本地服务器支持视频 Range 请求，所以进度条可以拖动。它只监听 `127.0.0.1`，iPhone 不能直接通过局域网访问；要在 iPhone 上测试，请先按后面的章节部署到 Vercel 或 GitHub Pages。

如果要在本地测源管理与多源搜索，用一体化服务器（静态文件 + `/api/*`）：

```bash
# 终端 1：开发模式，仅允许 loopback 源，免口令
AH_ENV=development AH_DEV_ALLOW_PRIVATE=1 AH_DEV_NO_AUTH=1 node tools/ah-server.js 4173

# 终端 2：合法的本地 mock 源（自造 JSON + CC0 短片）
node tools/mock-cms.js 4180
```

打开 <http://127.0.0.1:4173/#/sources>，添加 `http://127.0.0.1:4180/api.php/provide/vod`（勾选授权），再到搜索页搜 `Big`。

一键跑完界面回归 + 源管理 + 多源搜索：

```bash
node tools/e2e.js
```

## 部署到 Vercel（海外 / 备用入口）

Vercel 免费 Hobby 计划不需要信用卡；静态 PWA 和 `/api/*` 在同一个域名下。没配置源时，它就是一个普通的静态 App。注意 `*.vercel.app` 在国内常被 DNS 污染；国内使用请优先选下一节的 **EdgeOne Pages**。

1. 把代码推到 GitHub（`AAAHaiovo/ah-cinema`）。
2. 打开 <https://vercel.com>，用 GitHub 登录 → **Add New → Project** → 导入仓库。
3. 配置：Root Directory `./`，Framework Preset `Other`，Build Command 留空，**Output Directory 填 `docs`**。
4. 在 Environment Variables 里加：
   - `AH_API_TOKEN`：随机口令，App 的「访问口令」填这个。生成：`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
   - `AH_SIGNING_SECRET`：另一个随机值，只放 Vercel，**不要**填进 App。
   - `AH_ENV=production`
   - 可选：`AH_ALLOWED_ORIGINS=https://aaahaiovo.github.io`、`AH_SEARCH_MAX_PAGES=2`、`AH_PROXY_TTL_SECONDS=43200`。
   - **不要**设置 `AH_DEV_NO_AUTH` 或 `AH_DEV_ALLOW_PRIVATE`。
5. Deploy 完成后打开 `https://<项目名>.vercel.app/api/health`，确认 `ok:true`、`authRequired:true`、`proxyReady:true`。缺少口令或签名密钥时，受保护接口会直接 503，不会变成公开代理。
6. 打开 App → 我的 → 源管理：服务地址留空（同源），口令填 `AH_API_TOKEN`，点「保存并检测」。
7. 添加你有权使用的 Apple CMS 地址并勾选授权，然后到搜索页按回车搜索。

> GitHub Pages 版仍然保留。要在 Pages 版里用多源搜索，在源管理把服务地址填成 Vercel 地址、口令相同即可（CORS 已允许 `aaahaiovo.github.io`）。

## 部署到腾讯云 EdgeOne Pages（国内网络推荐）

`*.vercel.app` 在国内常见 DNS 污染，手机蜂窝网络往往打不开。EdgeOne Pages 提供国内可访问的默认域名，并且同样能把静态 PWA 和 `/api/*` 放在同一个域名下。免费版够个人使用：Node 函数默认 30 秒超时、单次响应上限 6 MB、每月 300 万次调用。

> **默认域名在中国大陆只能用「预览」链接访问，链接 3 小时过期。** 这是平台的合规限制，不是部署失败。长期使用有两条路：绑定自定义域名（选「全球可用区（不含中国大陆）」无需 ICP 备案），或改用下面的 **SCF 函数 URL** 方案（免费、不用域名）。

> 首次使用需要在腾讯云完成**实名认证**（大陆节点要求）。

1. 把代码推到 GitHub（`AAAHaiovo/ah-cinema`）。仓库里的 `edgeone.json` 已经写好构建配置。
2. 打开 EdgeOne Pages 控制台：<https://console.cloud.tencent.com/edgeone/pages> → 创建项目 → 导入 Git 仓库 → 选择 `AAAHaiovo/ah-cinema`、`main` 分支。
3. 构建配置（与 `edgeone.json` 一致）：
   - 安装命令：`npm install`
   - 构建命令：`npm run build:edgeone`
   - 输出目录：`docs`
   - Node 版本：`20`
4. 环境变量（Production）：

   | 变量 | 值 | 说明 |
   |---|---|---|
   | `AH_ENV` | `production` | **必填**；不设会落在开发模式 |
   | `AH_API_TOKEN` | 随机口令 | App 的「访问口令」填这个 |
   | `AH_SIGNING_SECRET` | 另一个随机值 | 只放服务端，不要填进 App |
   | `AH_PROXY_MAX_BYTES` | `5500000` | 给 6 MB 响应上限留余量 |
   | `AH_ALLOWED_ORIGINS` | 可选 | 额外允许的跨域来源 |

   生成随机值：

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

   **不要**设置 `AH_DEV_NO_AUTH` 或 `AH_DEV_ALLOW_PRIVATE`。

5. 点击部署。完成后控制台会给出 `https://<项目名>.edgeone.app` 之类的默认域名。
6. 打开 `https://<域名>/api/health`，确认返回 `"ok":true`、`"missingEnv":[]`、`"authRequired":true`、`"proxyReady":true`。若返回的是 HTML 403，先检查控制台里的「默认域名访问保护」，不是 CORS 问题。
7. 打开 App → 我的 → 源管理：服务地址留空（同源），口令填 `AH_API_TOKEN`，点「保存并检测」。
8. iPhone Safari 打开该域名 → 分享 → 添加到主屏幕。

部署后的限制：

- **单次响应上限 6 MB**：m3u8 清单没问题；HTTPS 视频直链和 HTTPS 分片默认直连、不经过函数；HTTP MP4 通常超过 6 MB，在 EdgeOne 上无法通过代理播放，优先用 HTTPS 直链或 HLS。
- **Node 函数默认 30 秒超时**：搜索（8 秒）和代理（15 秒）都在时限内。
- **改了 `server/` 下的代码**：本地先运行 `npm run build:edgeone` 重新生成 `cloud-functions/api/[[default]].js` 并提交；平台构建时也会再跑一次，提交产物是为了本地预览和回滚。
- 本地可以用 `npm run dev:edgeone` 模拟 EdgeOne（静态 + `/api`，端口 4199）。

> Vercel 版仍然保留，可作为备用。两个后端可以同时存在，App 的「服务地址」填哪个就用哪个。

## 部署到腾讯云 SCF（免费、无需域名）

不想买域名时用这条路线：**前端继续放在 GitHub Pages，API 放到腾讯云 SCF 函数 URL**。函数 URL 的默认域名永久有效、不需要 ICP 备案，也不用绑定自定义域名。

```text
iPhone Safari
  ├─ 应用界面：https://aaahaiovo.github.io/ah-cinema/
  └─ API：https://<函数URL>/api/*（请求带访问口令）
```

### 1. 本地打包

```bash
npm run build:scf
```

产物：

- `scf/index.js`：函数代码（已提交，便于回滚）

1. 打开 [SCF 控制台](https://console.cloud.tencent.com/scf/list)，地域选 **广州**（或离你近的地域）。
2. 新建 → 从头开始：
   - 函数名称：`ah-cinema`
   - 运行环境：**Nodejs 20**（没有就选 Nodejs 18）
   - 提交方法：**上传 ZIP 包**，选择 `scf/ah-cinema-scf.zip`
   - 执行方法：`index.main_handler`
3. 高级设置：
   - 超时时间：**30 秒**（默认 3 秒，必须改）
   - 内存：256 MB
4. 环境变量（四条，值不要带引号）：

   | 名称 | 值 |
   |---|---|
   | `AH_ENV` | `production` |
   | `AH_API_TOKEN` | 你在 App 里要填的口令 |
   | `AH_SIGNING_SECRET` | 另一个随机值，只放服务端 |
   | `AH_PROXY_MAX_BYTES` | `5500000` |

5. 创建函数。

### 3. 开启函数 URL

函数详情 → **函数 URL** → 启用 → 选择 `$LATEST`（若要求先发布版本，就先发布一个版本或别名）→ 复制公网地址：

```text
https://<app-id>-<url-id>.ap-guangzhou.tencentscf.com
```

打开 `https://<函数URL>/api/health`，确认返回 `"ok":true`、`"missingEnv":[]`、`"authRequired":true`。

### 4. 在 App 里配置

打开 GitHub Pages 版 App → 我的 → 源管理：

- **服务地址**：填函数 URL，结尾不要带 `/`，也不要加 `/api`；
- **访问口令**：填 `AH_API_TOKEN`；
- 点「保存并检测」。

CORS 已允许 `https://aaahaiovo.github.io`；其他域名需要在环境变量里加 `AH_ALLOWED_ORIGINS`。

### 限制与维护

- 单次响应上限按 **6 MB** 处理，`AH_PROXY_MAX_BYTES=5500000` 留余量；HTTP MP4 通常超限，优先 HTTPS 直链或 HLS。
- 函数 URL 的超时以控制台配置为准（建议 30 秒）；搜索 8 秒、代理 15 秒都在时限内。
- 多源搜索的 NDJSON 会先在函数内缓冲、再一次性返回，结果出现稍慢，但内容一致。
- 改了 `server/` 下的代码后：运行 `npm run build:scf` → 在控制台「函数代码」重新上传新的 ZIP → 保存并测试。

## 部署到 GitHub Pages

GitHub Pages 免费版需要 **public（公开）仓库**。代码会公开；链接、观看历史、收藏、进度只存在你自己的设备里，不会上传。

1. 在 GitHub 新建一个仓库，例如 `ah-cinema`。
2. 在项目文件夹里执行（把 `<你的用户名>` 换成你的 GitHub 用户名）：

```bash
git init
git add .
git commit -m "AH 影视 v0.8.13"
git branch -M main
git remote add origin https://github.com/<你的用户名>/ah-cinema.git
git push -u origin main
```

3. 打开仓库的 **Settings → Pages**：
   - Source 选 **Deploy from a branch**
   - Branch 选 **main**，文件夹选 **/docs**
   - 保存
4. 等 1～2 分钟，访问：

```text
https://<你的用户名>.github.io/ah-cinema/
```

5. iPhone 上用 **Safari** 打开这个地址 → 分享按钮 → **添加到主屏幕**。之后从主屏幕打开就是全屏 App 的样子。

App 使用相对路径和 hash 路由，放在 `/<仓库名>/` 子路径下也能正常工作；`docs/.nojekyll` 已放好，GitHub Pages 不会用 Jekyll 处理这些文件。

>
> **主屏图标还是旧样式？** iOS 会按 URL 缓存 `apple-touch-icon`。图标地址带版本号（当前 `?v=088`）；如果主屏仍是直角旧图标，删除旧图标后重新「添加到主屏幕」即可。

## 数据与隐私

- 粘贴的链接、播放进度、收藏、搜索记录、设置都存在当前设备的浏览器里（IndexedDB / localStorage），不上传。
- 本机视频文件存进浏览器的 IndexedDB，**不会上传**，也**不在 JSON 备份里**；备份只包含链接、进度、收藏、设置等小数据。
- 删除本机视频会同时删除浏览器里保存的文件、进度和收藏。
- 添加的源、订阅、远程详情缓存（只含元数据和签名地址）也存在 IndexedDB；视频文件不会缓存。备份 JSON 包含已授权的源与订阅，但**不包含访问口令**。
- 访问口令只保存在当前浏览器的 `localStorage`（`ah-api-token`），不写入设置、不进备份、不出现在网址里。
- App 没有账号、没有统计、没有第三方脚本。外部请求只有：你自己粘贴的视频地址、B 站官方播放器、你自己的 API 服务，以及你添加的源（经你的服务或签名代理请求）。

## 已知限制

- **只播链接本身**：App 不会解析普通网页、网盘或平台会员页，也不会抓取视频地址或绕过 DRM。这类链接即使点了“仍要尝试”，也大概率无法播放。
- **网络直链需要对方允许**：服务器若限制 Referer、需要登录、禁止直接播放，或证书有问题，播放器会报错，这不是 App 能绕过的。
- **HLS `.m3u8`**：Safari / iPhone 原生播放，桌面 Chrome / Edge 通过自托管的 hls.js 播放。若源站限制跨域或防盗链，可在源管理 → 高级开启「HLS 分片走代理」（会增加流量）。MP4（H.264 + AAC）兼容性最好。
- **源由你自己负责**：源失效、超时、地区限制、需要登录、防盗链都可能导致搜索或播放失败。App 只做 JSON / XML 解析和转发，不会绕过这些限制；也不会推荐或代找任何源。
- **多源搜索需要服务**：GitHub Pages 纯静态版必须先配置 Vercel / EdgeOne 地址和口令；没有配置或离线时，本地搜索仍然可用。
- **免费服务的限制**：Vercel 函数有响应体大小、执行时长和带宽限制；EdgeOne 免费版单次响应上限 6 MB、默认 30 秒超时；SCF 函数 URL 同样按 6 MB 响应上限处理，超时需在控制台调到 30 秒。签名代理默认只承载 m3u8 清单和必要的 HTTP 分片，HTTPS 分片通常直连；HTTP MP4 超过 6 MB 时无法通过代理播放。
- **B 站嵌入依赖哔哩哔哩**：需要能访问 `player.bilibili.com`；iframe 里的清晰度、倍速、字幕由 B 站播放器提供，App 自己的这些按钮不适用于嵌入条目。上传者删除视频、改为不可播放、地区限制或登录限制都会导致画面无法加载。
- B 站 iframe 在部分浏览器/无头测试环境里截图是黑屏，这是截图合成的限制，不代表页面结构有问题；真实 iPhone Safari 上还需人工确认能否正常起播和全屏。
- **本机文件依赖浏览器存储**：容量受浏览器配额限制（单个文件上限 2 GB，实际可用空间可能更小）；Safari 长期不用站点后可能清理数据，重要文件请保留原始文件。
- **断网只能打开应用壳**：首页、片库区域、我的视频、历史等界面可以离线打开；网络源和链接的视频播放仍需要联网，只有本机文件可以完全离线播放。
- iPhone 的安装、全屏和原生播放器行为受 Safari 限制；PWA 需要 HTTPS（GitHub Pages 满足）。安装后长期不打开，Safari 可能清理站点数据，建议偶尔用“导出备份”留一份 JSON。
- 播放器右下角的**方向按钮**用于手动横屏：iPhone 开启“竖排方向锁定”时，旋转手机不会改变网页方向，点这个按钮会把播放器旋转 90° 铺满屏幕；如果手机能自动旋转，转到横屏后按钮会自动隐藏，页面按正常横屏布局显示。
- 本地预览服务器只绑定 `127.0.0.1`，iPhone 要通过部署后的 HTTPS 地址访问。

## 以后可以怎么扩

1. **整片离线下载**：用 OPFS / IndexedDB 分片存视频，加上下载队列、占用空间、断点续传；这是 P1，不是当前版本。
2. **远程访问**：如果家里有 NAS，可用 Tailscale 等私有网络在外网访问，不需要把片库公开。
3. **更聪明的链接识别**：只做公开、明确的官方 embed 支持（例如其他平台的官方播放器），不做网页解析、抓取或 DRM 绕过。
4. **真实 iPhone 验收**：部署后用 Safari 添加到主屏幕，重点验证全屏、锁屏控制、后台暂停、蜂窝网络播放和存储清理。
5. **重新加入正式片库**：如果以后要内置影片，只放公共领域 / 开放授权 / 你自己有权利的内容，并把海报路径加进 `docs/sw.js` 的 `SHELL`、升一版缓存。
